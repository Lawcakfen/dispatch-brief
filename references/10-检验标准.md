# 检验标准（自用版 + 公开版，两套判据）

> **这份是「标准」。`audit_deep.py` 是「执行」。**
>
> ★★ 标准里列了哪几条，脚本就必须跑哪几条 —— 由 `audit_deep.py --spec` 自动比对，
> 不一致就报错。**否则文档会变成下一个「两处真相」。**

## 为什么必须两套

自用版和公开版的判据是**相反**的，合成一套必然有一半规则失效：

| | 自用版 | 公开版 |
|---|---|---|
| 私有词 | **必须存在**（否则认不出是哪个客户） | **必须 0** |
| 本机路径 | 允许 | 必须收敛到配置 |
| 脚本 | 要能真跑 | 不跑（读者自己装） |
| 内容完整性 | 不能比旧版少 | 不适用（已脱敏） |

## A · 自用版（`skills/productivity/super-agent`）

| # | 判据（怎么算过） | 为什么有这条 | 不过怎么办 |
|---|---|---|---|
| **A1** | `SKILL.md` frontmatter 的 `name` 匹配 `[a-z0-9][a-z0-9-_]{1,63}` | name 不合法 → skill 加载器可能整个不认，且只有换会话才发现 | 改名，别用中文/空格 |
| **A1b** | description 非空且含 `Use when` | 这是触发条件。写空的 → 该用的时候不会加载 | 补一句「Use when …」 |
| **A2b** | 每份 reference ≥ 1000 字符 | **实测踩过**：删了源之后重跑生成器，10 份全被写成空壳，脚本还「成功」退出 | 同上；先看 `git log` 找回上一版 |
| **A4** | 主干 ≤ 400 行 | 超过说明它在偷干 references 的活 → 上下文吃满、定位变慢 | 把细节挪进 references |
| **A5** | SKILL.md 声称「二十条硬判据」→ 实际编号条目数 == 20 | **实测踩过**：写「20 条」但只有 17 条，没人会重数 | 补到 20 条或改标题 |
| **A6** | 声称「N 条坑」→ `06-坑清单.md` 实际行数 == N | 同上，数字会随去重变化 | 改数字，或干脆不写数字（更好） |
| **A7** | 无 `TODO:` / `FIXME:` / `【待补】` / `<占位>`（表格行不算 —— 那里在引述案例） | 留个 TODO 就等于留个洞，而且一个月后自己都不记得 | 补完或删掉那句 |
| **A8** | `git status --porcelain` 为空 | 有未提交改动 = 这次的改动还没进备份，机器一坏就丢 | 跑 `backup_skill.py` |

**信息项（不判通过/失败，只报告数字）**

```
A10  绝对路径出现次数 —— 自用版允许，但数量突变要警觉（可能误贴了外部内容）
```

## B · 公开版（`repos/super-agent-brief-writing`）

| # | 判据（怎么算过） | 为什么有这条 | 不过怎么办 |
|---|---|---|---|
| **B1** | 19 个私有词 + 2 条路径规则，命中 0 处 | **实测漏过两处**（示例书店活动海报设计 / 示例·小红书），在公开仓库躺了半年 | 往 `publish-map.json` 补词，重跑 `build_public.py` |
| **B1-注** | `C:\Users\<某人>` 这种**已脱敏的占位**不算泄漏 | 第一版按子串查 → 把占位写法判成泄漏（假红 2 处） | 已改成按「路径段」查 |
| **B2** | 正文提到的 `references/` `templates/` `scripts/` 文件都存在 | **实测 34 处死链**（正文互指旧文件名）+ `scripts/scan_projects.py` 被引用但没发 | 补映射或把文件发上去 |
| **B3** | 不出现合并前的文件名（01-派单与指令.md / 02-盯梢与自动化.md …） | 老名字在正文里 = 读者点不到，且说明脱敏只做了一半 | 走 B2 的修法 |
| **B4** | frontmatter `name` 合法 | 读者装不上就没意义 | 修 name |
| **B5** | README 不写死行数 / 文件数 / `Files: N` | **实测踩过**：README 写「402 行」「不含实现代码」，全是假的；我自己又在 v2.0 说明里放了「Files: 18」 | 改成不写数字（数字一定会过期） |
| **B6** | `LICENSE` 存在且含 MIT | 没协议 = 别人不敢用 | 补 LICENSE |
| **B7** | `scripts/*.py` 全部语法正确 | **实测踩过**：`py_compile(cfile=os.devnull)` 在 Windows 上全报错（7/7 假红） | 用 `compile()` 只验语法 |
| **B8** | scripts 里无 `<库根>` / `C:\Users\<真名>` | 带本机路径发布 = 泄漏 + 别人跑不了 | 改成读 `paths.py` |
| **B9** | 无 `sk-` / `ghp_` / `AKIA` 形状字符串、无手机号、无邮箱 | 一次误贴 key 就是永久泄漏（git 历史删不掉） | 立刻吊销那个 key，再删文件 |
| **B10a** | `git status` 空 | 有未提交 = 远端和你以为的不一样 | 提交并 push |
| **B10b** | 本地 HEAD == `origin/main` | 分叉 = 你不知道哪边是真的 | push 或 pull |

## C · 交叉逆推（两套之间的一致性）

| # | 判据 | 为什么有这条 | 不过怎么办 |
|---|---|---|---|
| **C1** | repo 里**每一个**生成文件 == `build_plan(自用版)` | **这是最狠的一条。** 它同时抓三种病：①有人手改 repo（下次 build 静默冲掉）②改了源但没重跑生成 ③生成器漏了某个变换 | 跑 `build_public.py`；若不解决，说明有人手改过，用 `git diff` 找出来 |
| **C1b** | 计划里的文件在 repo 里都存在 | 缺文件 = 读者拿到残包 | 同上 |
| **C2** | repo 的 `references/` 里没有计划外的文件 | 多出文件 = 手放的，脱敏没走过门禁 | 删掉或纳入生成 |

## 失败的优先级（不是所有红都一样急）

```
立刻修   B9（key 泄漏）· B1（私有词）· A8（未提交）
今天修   C1 / C2（逆推失败）· A2b / A3（内容丢了）· B5（假数字）
可以拖   A5 / A6（声称的数字）· B8（路径没收敛）
```

**★★★ 最重要的一句：门禁全绿 ≠ 内容正确。**
2026-11-21 实测过 —— 私有词 0、死链 0、旧名 0，全绿，
但内部账本（publishing-status）照样被发到了公开仓库上。
**所以 B 轨之外必须有人看一眼 diff。这一条没法自动化。**
