## 五条铁律

### ① 内容来源必须唯一且写死路径

```
✗ 「把之前的资料整理一下」        → WB 会自己找、自己理解、自己编
✓ 「唯一内容来源：<库根>\...\<诗名>.md（约 623 行）」+ 「该文件里没有的，留空，不要填」
```

**★★ WB 的头号毛病是「编得很顺、但没真发生」。** 不给唯一来源，它就会用「合理」补「真实」。

### ② 「不许编」要写成可执行的核对细则，不是一句口号

```
只搬运该文件里已有的内容，一个字都不许新增解读、不许润色得更文学
该文件里标了「⚠️/待确认/存疑」的内容，一律不搬
不许凭记忆补诗句/数据 —— 文件里没有就只留标题
```

**★ 抽象禁令无效，要列「哪些字段不许碰」「哪些标记要跳过」。**

### ③ 形状要「可判定」，不要给自由

```
✗ 「20 分钟或者 2 小时都可以」 → 你听到的是「随便准备点」
✓ 「十来分钟就够 —— 说清三件事：它是什么、你在什么场景用它、它哪里还不够」
```

**★ 给自由不是给形状。** 你自己就是「没有形状的东西做不动」的人，写给执行方的 Agent 同理。

### ④ 视觉/审美要给「禁止清单」，不只给「要什么」

**★★★★ 这一条最容易被漏，也最容易毁掉一个交付物。**

写「干净、可读、有秩序感」没用 —— WB 会理解成「做得高级一点」，然后交出深色背景 + 大字居中 + 缓慢淡入。

必须逐条禁止：

```
✗ 深色背景 / 黑底金字
✗ 缓慢淡入、视差、粒子、飘动
✗ 手写体、书法字体、宣纸纹理
✗ 大字号居中占满整屏
✗ 渐变背景、玻璃拟态、发光文字
✗ 动画超过 0.3 秒
```

**★ 并且把「为什么禁」写进指令** —— 例：收件人是「反对把诗神秘化」的老师，所以这份页面的审美方向必须是「能逐字读」，不是「让人不敢读」。

**★★ 有了理由，WB 在边界情况才判得对；只给清单，它会在清单外发明。**

### ⑤ 验收清单 + 交付单一化

```
□ 双击 index.html 能打开，断网也完整
□ 文件里搜不到 http://（除注释）
□ 手机竖屏 375px 能读，无横向滚动
□ 打印预览：各节另起一页，无按钮
□ 没有任何一句是你自己加的解释
```

**★ 一次只交一个文件、一个路径。** 多文件交付你没法「粘一下就完事」。

**★ 结尾要求 WB 回报三件事**（本次用的）：① 各节数量 ② 收了几个条目 ③ **哪些地方你留了「待补」** —— 第 ③ 项是「不许编」的可验证出口。

## 指令骨架（八节，照填）

```
一、产物        —— 一个文件 + 绝对路径 + 技术规格（单文件/无外链/响应式/打印）
二、内容来源    —— ★ 唯一来源路径 + 「不许编」的执行细则
三、结构        —— 逐屏/逐节写清，标出哪一屏最重要
四、视觉要求    —— 要做 / ★ 不要做（逐条禁止 + 理由）
五、交互        —— 只列允许的，并明写「以下一律不做」
六、验收清单    —— WB 自己逐条过
七、出错时的处理 —— 缺内容怎么办（留空 + 灰字「待整理」）、不确定怎么办（宁可多不可少）
八、交付        —— 回报哪三件事
```

**★★ 第七节是绝大多数指令漏掉的** —— 不写「出错时怎么办」，WB 就会自己发挥，而它发挥的方向永远是「补全」。

## 三个高频产物类型

### A. 单文件 HTML「礼物页 / 纪念页」

场景：送给老师、送给客户、给参与者留档。
**★ 关键判断：这是礼物不是作品集 —— 第一屏应该是一封短信，不是标题。**

模板：`templates/gift-webpage-brief.md`（本次实战 7.9 KB 指令的骨架，可直接改）

### B. 视觉产物（海报 / 长图 / 预览页）

- 给**参考图 + 设计规范**，不要用语言描述风格
- **先出一张样板 → 确认 → 再批量**（这条省下的返工最多）
- 尺寸/DPI/命名规则写死（例：`720×1080`、`MMDD-系列名.png`）

### C. ★★★★★ 改造一个已有的代码文件（不是从零生成）
**→ 详见 `references/refactor-existing.md`**　先读后改、锚点选择、删嵌套块、改完必验语法、截图必看。

## ★★★★★ 七轮实测出来的四条（内容看板 v1–v7，2026-11-14 → 11-16）

**这不是理论，是七轮派单里量出来的。每一轮都有具体的数字。**

### ① 指令长 ≠ 做得慢。模糊才慢

```
v7：424 行 / 14.9KB　→　WB 02:54 开始，03:05 收工，11 分钟
改的是：素材池重构（数据层 + HTML + CSS + JS 三层）+ 状态词统一
```

**★ 反直觉：直觉是「给这么多要求，它得做很久」。**

**★★ 实际是「不用猜，所以做得快」—— 它不需要来回问，也不需要自己发明做法。**

**★★★ 对照：早期 v1/v2 指令 200 行左右，反而来回改了 4 次。**
**差别不在长度，在「有没有把判断留白」。**

**★★★★ 所以：宁可写长，不要留白。留白的地方它一定会填，而且填的是它的假设，不是你的意思。**

### ② 可勾选的验收清单，它会逐条报 —— 连「部分通过」都报

**v7 的清单 22 条，它的回报长这样：**

```
| 条 | 结果 |
|---|---|
| 1/2/3/5 | ✅ 标题与 114·150 与脚本打印一致；DOM 桩 114 卡 / 148 角度 |
| 4 | ✅ 真机 Edge headless + CDP：点第一张卡 → open: false→true，.po-body 高度 >0 |
| 12 | ⚠ 部分：全文连续 ** = 0（真机 innerText 实测）；半角 | = 2 处，见③ |
| 21 | ✅ 真机 Edge：Runtime.exceptionThrown / Log error / console.error 全为 [] |
```

**★★ 关键：它没有把「⚠ 部分」糊成「全部通过」。**

**★★★ 为什么能这样：因为每条都写成「能动手验的动作」，不是「请检查页面」。**

```
✗ 请检查筛选功能是否正常
✓ 点「我是微光·小红书」+「讲述型」→ 页面显示「这个组合暂时没有素材」，0 张卡，★ 不许退回全部
```

**★★★★ 差别的本质：前者要它「评价」，后者只要它「执行并观测」。评价可以糊，观测不能糊。**

### ③ ★★★★★ 但它不报你没列的东西 —— 这是自动化验收的根本局限

**v7 的 22 条全绿。但我扫一眼截图就发现：素材卡标题太长，标题和来源糊成一行。**

**★★ 那条我没写进清单，它就没报。不是它偷懒 —— 它按清单逐条验完了，清单之外它没理由去看。**

**★★★ 结论：**

> **验收清单不能替代人看一遍。**
> **它的价值是「把该核的事变成可核的」，不是「替你核完」。**

**★★★★ 所以流程必须是：它报清单 → 人扫一眼产物 → 人补上清单的盲区 → 下一轮把盲区写进清单。**

**★★★★★ 这个循环转三轮，清单才接近完整。第一轮的清单一定不全，别指望。**

### ④ 「超过 N 就停，不许凑」—— 防呆条款要写成「数量阈值 + 禁止动作」

**v7 里我写了：**

```
如果归位失败超过 10 个，停下来，把失败清单写进 memory，不要硬塞
★ 不要改匹配规则去凑，那会让错的也匹配上
```

**它的实际做法：**

```
归位成功 148 个，失败 2 个（#139 #140）
母素材写「／」、素材标题用「|」，全角半角不同
按指令「不改匹配规则去凑 / 不硬塞」，这 2 个没挂进任何卡片
页面加了一行灰字说明，标题仍写真实的 150
```

**★★ 它没有偷偷改规则把 2 个塞进去 —— 这正是这条防呆的价值。**

**★★★ 写法对照：**

```
✗ 请谨慎处理异常情况            ← 它不知道「谨慎」是什么
✗ 尽量保证数据准确              ← 无法判定
✓ 失败超过 10 个就停，写清单，不许改规则去凑   ← 有阈值、有动作、有禁令
```

**★★★★ 通用句式：「超过 <可数阈值> 就 <停下做什么>，不许 <某个具体动作>」。**

### ⑤ 「冲突时怎么办」让执行方自己解 —— 矛盾一定有，别指望写出无矛盾的指令

**v7 的三句话②要求「按带理由、更具体的那条执行，并在 memory 说明」。**

**它主动列了三条取舍：**

```
① A4 示例卡片头写「6 个角度」，A6③ 要求「符合的 / 总数」
   → 按更具体、带理由的 A6③，统一显示 X / Y 个角度

② A4 示例按钮数字口径混用（账号 22 = 主号角度数、类型 93 = 类型角度数、all 分别 114/150）
   → 按示例实现，并让筛选按【主号】判定（不查「可兼」），这样按钮数字 = 筛出的角度数

③ 验收清单「临时把 11-18 改 11-19 再改回」与「不许改 Outputs\drafts\」冲突
   → 按更严的边界，只在临时目录副本上改 PLAN_PATH，Vault 原文没动
```

**★★ 三条都是真冲突，三条都选对了。**

**★★★ 这说明：与其追求「写出一份没有矛盾的指令」（做不到），不如给一条「冲突时怎么办」的规则。**

**★★★★ 而且要求它「把取舍列出来」—— 这样你能复核它选得对不对。**

**★★★★★ 反例：如果你不写这条，它遇到矛盾会二选一，而且不说 —— 你事后才发现方向错了。**

---

## ★ 一句话总括

> **指令的质量不在「写得多全」，在「它不用猜、也不会偷偷凑、遇到矛盾会说」。**
>
> **清单管住「它不用猜」，防呆管住「它不偷偷凑」，冲突规则管住「它会说」。**
