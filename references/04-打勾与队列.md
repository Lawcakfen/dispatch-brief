# 队列完成匹配器 · 实现与回归

> 配套 `SKILL.md` §3.5.1。这里是完整的代码、5 条回归用例、以及三条保命规则的实测证据。

## 1. 数据结构：state 必须存「行数」，不只是 hash

```python
# scan_memory() 每个文件记三样
files[f] = {
    "mtime": os.path.getmtime(fp),
    "hash":  md5(txt)[:16],
    "path":  fp,
    "nlines": len(txt.split(chr(10))),   # ★ 关键：下次靠它切「新增段」
}
```

**★ 只有 hash 不够** —— 你知道「变了」，但不知道「哪一段是新的」。
**★★ 而「哪一段是新的」正是防止误判的唯一手段（见 §3）。**

---

## 2. 只取新增行的实现

```python
def new_memory_text(files, prev):
    """返回 (新增文本, 是否有可比基线)。无基线的文件一律不匹配 —— 宁漏不错。"""
    parts, has_base = [], False
    picks = sorted(files.items(), key=lambda kv: -kv[1]["mtime"])[:2]
    for fname, info in picks:
        txt = open(info["path"], encoding="utf-8", errors="ignore").read()
        all_lines = txt.split(chr(10))
        p = prev.get(fname)
        if not isinstance(p, dict) or not isinstance(p.get("nlines"), int):
            continue                      # ← 首次见到这个文件：只建基线，不打勾
        n0 = p["nlines"]
        if len(all_lines) <= n0:
            continue                      # ← 没新增 / 被重写截短：跳过
        parts.append(chr(10).join(all_lines[n0:]))
        has_base = True
    return chr(10).join(parts), has_base
```

**⚠️ 旧 state 格式（值是 hash 字符串）要兼容**，否则升级后第一次就崩：

```python
prev = {k: v if isinstance(v, dict) else {"hash": v} for k, v in prev.items()}
```

**★ 兼容后旧格式视为「无基线」→ 第一次升级只建基线，不会误打勾。** 这是有意的。

## 3. 匹配：英文标识符优先，中文短语兜底

```python
def _tokens(text):
    """抽 ASCII 标识符 —— 代码项目里天然唯一的指纹。"""
    out = set()
    for m in re.findall(r"[A-Za-z_][A-Za-z0-9_.\-]{2,}", text or ""):
        t = m.lower().strip(".-_")
        if len(t) < 3:
            continue
        if t in {"html","json","css","the","and","for","with","src","www","com",
                 "md","py","js","http","https"}:
            continue
        out.add(t)
    return out


def match_done(mem_text, queue_items):
    if not is_done_signal(mem_text):          # 条件①
        return None, "无完成信号"

    # ── 路线 A：英文标识符重合 ≥1 ──
    mem_t = _tokens(mem_text)
    best, best_score = None, 0
    for idx, it in enumerate(queue_items):
        qt = _tokens(it["text"] + " " + " ".join(x[1] for x in it["extra"]))
        if not qt or not mem_t:
            continue
        inter = qt & mem_t
        if len(inter) > best_score:
            best, best_score = idx, len(inter)
    if best is not None:
        return best, "标识符重合 %d 个" % best_score

    # ── 路线 B：中文短语重合 ≥4（纯中文任务走这条）──
    mt = _phrases(mem_text)
    best, best_score = None, 0
    for idx, it in enumerate(queue_items):
        qt = _phrases(it["text"] + " " + " ".join(x[1] for x in it["extra"]))
        inter = qt & mt
        if len(inter) > best_score:
            best, best_score = idx, len(inter)
    if best is None or best_score < 4:        # ★ 阈值 4，见 §4
        return None, "中文短语重合不足（%d 个，需 ≥4）" % best_score
    return best, "中文短语重合 %d 个" % best_score
```

**中文短语抽取（无分词库时的折中）：**

```python
def _phrases(text):
    out = set()
    # ① 按标点切成 3–14 字的片段
    raw = re.split(r"[，。；：、「」『』（）()／/\s\-—·…,.;:!?！？\[\]【】<>《》]+", text or "")
    for seg in raw:
        seg = re.sub(r"[*`#*>\]]", "", seg).strip()
        if 3 <= len(seg) <= 14 and seg not in STOP_PHRASES:
            out.add(seg)
    # ② 4 字滑窗（捕捉「复盘表单」这种没被标点分开的复合词）
    flat = re.sub(r"[^\u4e00-\u9fa5]", "", text or "")
    for i in range(len(flat) - 3):
        w = flat[i:i+4]
        if w not in STOP_PHRASES:
            out.add(w)
    return out
```

**`STOP_PHRASES` 必须有一份**（否则「现在」「为什么」「做完请」这种套话会凑够数）：
`现在 / 包括但不限于 / 为什么 / 做完请 / 的问题 / 并修掉 / 每条标出 / 今天 / 内容 / 工作 …`

## 4. 阈值 4 是实测出来的

| 用例 | 中文短语重合 | 判定 |
|---|---|---|
| 真命中：复盘表单 | **10 个** | 命中 ✓ |
| 无关的完成：改首页圆角 | **3 个** | 不命中 ✓ |

**★ 4 落在 3 和 10 中间，两边都有余量。**

**⚠️ 试过但失败的判据：**「要求至少 1 个短语长度 ≥5」
→ 中文按标点切出来最长往往是 4 字，**真命中被挡掉，回归从 5/5 掉到 2/5**。
→ **教训：判据要用「能分开两类」的那个，不是「听起来更严谨」的那个。**

## 6. 打勾：连续行一起搬

```python
def tick_item(path, q, idx, stamp):
    lines = list(q["lines"])
    it = q["items"][idx]

    # ① 摘出这一条的所有行（正文 + 续行），从待发段删掉（倒序删，行号才不串）
    drop = {it["line"]} | {ln for ln, _ in it["extra"]}
    for ln in sorted(drop, reverse=True):
        del lines[ln]

    # ② 重新定位「## ✅ 已完成」段（行号已变！）
    start = next((i+1 for i, l in enumerate(lines)
                  if re.match(r"^##\s*✅\s*已完成", l.strip())), None)
    if start is None:
        lines += ["", "## ✅ 已完成", ""]
        start = len(lines)

    # ③ 组装：去掉 **MM-DD** 前缀，追加「（完成于 …）」，续行原样带走
    text = re.sub(r"^\*\*[\d\-]+\*\*\s*", "", it["text"])
    dm = re.match(r"^\*\*([\d\-]+)\*\*", it["text"])
    new = [f"- [x] **{dm.group(1)}** {text}（完成于 {stamp}）" if dm else f"- [x] {text}（完成于 {stamp}）"]
    for _, raw in it["extra"]:
        new.append(raw)

    # ④ 跳过「（无）」占位再插入
    insert_at = start
    while insert_at < len(lines) and lines[insert_at].strip() in ("", "（无）"):
        if lines[insert_at].strip() == "（无）":
            del lines[insert_at]
            continue
        insert_at += 1
        if insert_at < len(lines) and lines[insert_at].startswith("## "):
            break
    lines[insert_at:insert_at] = new + [""]

    open(path, "w", encoding="utf-8").write("\n".join(lines))
    return text
```

**★ 第 ② 步的行号重算是必踩的坑** —— 删完条目还按旧行号插，会插到别的段里。

---

## 7. 一次扫描最多打几个勾

```python
MAX_TICKS_PER_SCAN = 3      # 防一次刷太多
```

**★ 为什么需要**：WB 可能一次写「已修 A，已修 B，已修 C」。
打勾后要**重新 `parse_queue()`**（行号变了）再匹配下一轮，最多 3 轮。

**★★ 但注意**：`while` 循环里拿的是同一个 `mem_text`，所以第二轮还是能命中 —— 这是对的。

## 8. `--dry` 必须真的不写

```python
if dry:
    # 只报告「会打哪一条」，绝不写文件
    it = q["items"][idx]
    nxt_i = q["items"][idx + 1] if idx + 1 < len(q["items"]) else None   # ★ 模拟 tick 后的下一条
    events.append({...})
    break
```

**★★ `next_item(qpath)` 在 dry 模式下会给错** —— 因为队列没真打勾，它会返回**当前**第一条（= 刚命中的那条）。
→ dry 分支要用 `items[idx+1]`，不是 `next_item()`。

## 9. 部署顺序（照做，别跳）

```
① 备份所有 _给WB.md
② 清 state → --init（只建基线，不打勾）
③ 连跑两次，确认完全静默
④ ★★ 人工复核：对着每个项目的 memory 看「哪些是真做完的」
   —— 如果历史上有未打勾的已完成任务，用 --set / 手工 tick 补，不要靠首次扫描自动补
⑤ 再跑一次，确认什么都不做
```

**★★★★ 第 ④ 步不能省。** 首次扫描「不打勾」是安全设计，但**代价是历史上已完成的任务不会被补上** ——
这需要人过一遍，或者用 `--backfill` 类的显式命令（默认关闭）。

# 首次真实运行抓到两个「自我污染」bug（2026-11-13）

> 背景：整套监管系统（证据包 + 入队队列 + 看板 + 心跳）当天下午搭完。用户说
> **「不用等明天 6:20 跑，现在跑一轮，看看有没有 bug」**。
> 一轮跑出两个真 bug，其中第一个会让整个系统输出荒谬值。
> **静态读代码两个都看不出来 —— 只有跑起来才现形。**

---

## Bug A：监控脚本读自己写的文件 → 全部项目显示「停滞 0 天」

### 症状

第一次 live run 的报告：

```
▸ 客户 A 小程序  客户项目｜停滞 0 天
▸ 客户 B      客户项目｜停滞 0 天（内容层 28 天）
▸ 11月-收钱线  停滞 0 天
▸ 示例的微信小店  停滞 0 天
▸ 示例新媒体运营  停滞 0 天（内容层停 11-10）
```

**★ 五个项目里四个「停滞 0 天」，而其中两个明明停了 3–4 天、一个停了 28 天。**

### 根因

系统在第 3.4 步给每个项目写了一份指令队列 `_给WB.md`（当天新建）。
`scan()` 用 `os.walk` 扫项目目录算 `max(mtime)` —— **`_给WB.md` 是项目根下的普通文件，被算成了「项目活动」。**

```
项目实际最后活动：11-09 / 11-10 / 11-07
我写 _给WB.md 的时刻：11-13 10:32 / 10:59
→ max(mtime) = 11-13 → 停滞 0 天
```

**★★★ 这是自指陷阱：监管脚本自己就是被监管目录的写入者。**

### 修法

```python
for dp, dirs, fs in os.walk(p):
    dirs[:] = [x for x in dirs if x not in SKIP_DIRS]
    for f in fs:
        # ★★★ 跳过我自己写的元数据文件 —— 否则「停滞天数」会被我自己的写入拉新
        if f == "_给WB.md":
            continue
        fp = os.path.join(dp, f)
```

**改动极小（一行），但必须精确** —— 只排除自己写的那个文件，不要顺手排除所有 `_` 开头（项目里可能有真实的 `_index.md`）。

### 修复后实测

```
客户 A 小程序       2026-11-13 12:18 → 停滞 0 天     ← 真的在动（执行 Agent 在改代码）
11月-收钱线      2026-11-13 10:59 → 停滞 0 天     ← 今天新建，正常
示例新媒体运营    2026-11-10 14:23 → 停滞 3 天     ← 修好了
示例的微信小店    2026-11-09 09:29 → 停滞 4 天     ← 修好了
某本地地图项目   2026-11-07 19:02 → 停滞 6 天
客户 B          2026-10-16 08:31 → 停滞 28 天
```

### 为什么这个 bug 特别危险

**它不是崩溃，是「输出看起来很正常」。** 一份写着「停滞 0 天」的报告，读起来像「一切都在推进」——
用户会因为这份报告而**不去碰任何一个真正停了的项目**。**静默的错误比报错贵得多。**

### 泛化判据

> **任何「扫目录 → 算活动 → 报警」的脚本，动手前先问：这个目录里有哪些文件是我（或兄弟 cron）写的？**
> 日志、队列、缓存、状态文件、`.tmp`、我注入的 markdown —— **全部要排除**。
> 否则监控会自己给自己制造「一切正常」的假象。

**同类风险清单**（本项目里）：
- `_给WB.md`（指令队列）✅ 已排除
- `_进度总表.md`（在 `projects/` 根，不在项目内，天然不在扫描范围）
- 看板目录 `_看板/`（以 `_` 开头，`scan()` 已跳过）
- 执行 Agent 的 `.workbuddy/`（在 `SKIP_DIRS` 里）✅

## Bug B：汇报段里的「汇总行」被当成第 7 个项目

### 症状

看板顶部写「**7 张卡**」，但汇报只有 6 个项目。多出来的那张卡叫：

```
另有 17 个项目已停 21 天以上：拆解爆款视频、慧莹&3+、示例作者媒体运营、…
```

### 根因

看板的 `reports` 解析器判据是「以 `- ` 开头 + 含 `：`」。
而 prompt 要求 agent 在汇报末尾写一行概括：

```
- 另有 17 个项目已停 21 天以上：<名单>
```

**这行两个条件都满足 → 被当成一个叫「另有 17 个项目已停 21 天以上」的项目。**

### 修法：用结构判据，不依赖措辞

```js
const body = L.replace(/^-\s*/,'');
// ★★ 只有带「｜ 建议」的才是项目行 —— 汇总行不带，自动跳过
if (!/｜\s*建议/.test(body)) continue;
const ci = body.indexOf('：');
if (ci < 0) continue;
```

**★★★ 为什么这比「排除含『另有』的行」好**：措辞会变（今天是「另有 N 个」，明天可能是「其余」「还有」「未列的」）。
**真正的项目行有一个不变的结构特征：它一定有 `｜ 建议`。** 用这个判，换措辞也不会破。

### 这是同类问题的第二例

`SKILL.md` §3.6 已记过第一例：「注入的新段落被汇报解析器吃掉」→ 修法是「遇到下一个 `##` 就停」。
**两例合起来的完整规则是：**

```
往一个按「段 + 行」解析的文本格式里加内容时，要同时守住两层边界：
  ① 段边界 —— 每个解析器读到不属于自己的 ## 段就 break
  ② 行边界 —— 每个解析器用【结构特征】认自己那行，不靠措辞或位置
```

**本项目里同时有三个解析器**（`reports` 汇报行 / `rawFor` 原文 / `todosFor` 待发），
**每加一种新内容，都要回头检查另外两个会不会吃进来。**

## 从这一轮得到的流程教训

### ① 「跑起来」比「读代码」有效一个数量级

两个 bug 都是**看代码看不出来**的：
- Bug A 需要"项目里恰好存在我今天写的文件"这个运行时状态
- Bug B 需要"prompt 真的让 agent 写了汇总行"这个运行时输出

**★★ 所以：新建或大改的 cron，当天必须手动 `action=run` 一次，不能等第一次自然调度。**

### ② run 之后要看的东西，不是 `last_status`

```
✗ last_status: ok        → 它只证明「跑完了」，不证明「跑对了」
✓ 读 output 文件正文     → 确认脚本输出真的被注入（不是 agent 自己硬撑）
✓★ 看数据是否荒谬        → 本次就是靠「5 个项目全 0 天」这个不可能值发现的
```

**★★★ 判据：跑完之后先找「不可能的值」** —— 全 0、全相同、比昨天倒退、单位错、条数比预期多 1 或少 1。
**这类值比任何日志都响。**

### ③ 修完必须重跑一轮，而且要对比两轮

- 第一轮：发现「停滞 0 天」和「7 张卡」
- 修 Bug A → 第二轮：停滞天数正确了，但**卡还是 7 张**（Bug B 没修）
- 修 Bug B → 第三轮验证：6 张卡

**★★ 一轮只能暴露一部分 bug。修一个就重跑一次，别攒着一起验。**

### ④ 用真实临时目录做回归测试（不要手工改 state）

```python
tmp = tempfile.mkdtemp(prefix="hermes-verify-")
proj = os.path.join(tmp, "项目A"); os.makedirs(proj)
real = os.path.join(proj, "真实产出.md"); open(real,"w").write("x")
os.utime(real, (time.time()-10*86400,)*2)      # 真实产出：10 天前
open(os.path.join(proj,"_给WB.md"),"w").write("...")   # 元数据：刚刚
pw.ROOT = tmp                                   # monkeypatch 模块级常量
st = pw.scan()
assert 9.5 < (time.time()-st["项目A"]["mtime"])/86400 < 10.5   # 必须取到 10 天
```

**★ 顺带加一条对照组**：「没有 `_给WB.md` 的项目照常扫到」—— 防矫枉过正（把整个项目漏掉）。

**★ Windows 注意**：`tempfile.gettempdir()` 可用，`/tmp` 不存在（native Python）。
