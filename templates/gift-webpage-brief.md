> 用法：复制 → 替换 `<>` 里的内容 → 整段粘给 WorkBuddy。

## 任务

为 `<收件人>` 做一份**网页礼物**：把 `<内容主题>` 整理成一个**单文件网页**。

## 二、内容来源（★ 唯一来源，不许自己发挥）

**唯一内容来源**：`<文件绝对路径>`（约 N 行）

## 三、页面结构（按顺序）

### 第一屏 · 一封信（★ 最重要的一屏）

- 打开后**第一眼是**一段写给收件人的信，不是标题、不是目录。
- 300–400 字，落款 `<署名>`。
- 信的内容由用户提供（见下方草稿），**你可以调整排版，但不许改写内容、不许扩写。**
- 信下面放一个「往下读 →」，点击平滑滚动到第二屏。

**信件草稿（原样使用）**：

> `<用户自己写的那封信 —— 不要代写，那是这份礼物里唯一买不到的部分>`

### 第二屏 · 总览

- 一张卡片/列表：序号 + 标题 + `<场次/日期>` + 一句话主旨。
- 点任一条 → 展开或平滑滚动到该区块。
- **一句话主旨必须来自原文件，不许自己总结出新的说法。**

### 第三屏 · 正文（主体）

每个条目一个区块，按原文件的**小节标题**分节，每节依次是：
① 节标题 ② 原文位置（行号/页码，照搬原文件标注） ③ 要点（原文 bullet → 易读列表）

### 第四屏 · 索引（★ 关键功能，不是装饰）

在原文件里找出**反复出现的核心词**，生成可点击索引：

```
词A · 词B · 词C · 词D · ……（从原文件提取，不要自己发明）
```

点击某个词 → **滚动到页面中第一次出现它的位置**，并给该处加 2 秒高亮。
**实现**：纯 JS 在渲染好的 DOM 里搜文本节点，不需要预置锚点表。

> ★ 这一层之所以是核心：原内容的组织方式就是「同一个词在多个条目里反复出现」，索引正好是这种读法的入口。

### 第五屏 · 时间线

按日期排列的横向/纵向时间线。**日期一律从原文件取，取不到就省略那一项，不要猜。**

### 页脚

一行小字：`<来源说明 · 整理自 … · 主讲/作者：…>`

## 四、视觉要求（★ 严格）

**这份页面是给 `<收件人的立场>` 看的。所以：**

### 要做

- **干净、可读、有秩序感。** 白底或极浅米色底，深灰字，正文行高 1.8。
- 用**细线分隔**代替大色块；用**字号层级**代替装饰。
- 引文与正文用**两种字体**区分（衬线 / 无衬线）。
- 留白要够，但不要大块空屏。

### 不要做（★ 逐条禁止）

```
✗ 深色背景 / 黑底金字
✗ 缓慢淡入、视差、粒子、飘动
✗ 手写体、书法字体、宣纸纹理
✗ 大字号居中占满整屏
✗ 任何"氛围感"设计
✗ 渐变背景、玻璃拟态、发光文字
✗ 动画超过 0.3 秒
```

**理由写进代码注释里也行**：这份页面的审美方向＝**能逐字读**，不是**让人不敢读**。

## 七、出错时的处理

- 原文件里某节不全 → **保留已有的，缺的留空，写一行很小的灰字「（此处整理待补）」，不要补。**
- 找不到日期 → **不显示日期，不要猜。**
- 不确定某个词要不要收进索引 → **收，宁可多不可少。**
